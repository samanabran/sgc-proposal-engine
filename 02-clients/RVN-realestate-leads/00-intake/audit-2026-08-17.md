Android exposes this only with explicit runtime permission and only on some OEM builds. What's actually in scope today: **manual** call logging inside the CRM (agent taps answered/not-answered/follow-up + writes a note after each call) — this is real, priced, catalogued (`crm_leads`). That requires one of: (a) RVN issuing company Android devices with a call-tracking app granted runtime permission, or (b) a cloud PBX / click-to-call number pool (agents dial through a virtual number, calls route through a telephony provider, and *that* generates verifiable logs). Neither has been discussed with RVN. **No catalogue row exists for either path** — this stays an open discovery item (`DISC-01` equivalent: logged in `client-brief.yaml: escalated_uncatalogued_requests` and `manifest.yaml: escalations`, status open).
